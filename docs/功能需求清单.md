# 模拟火车票售票系统 —— 功能需求清单

> 课题来源：`模拟火车票售票系统.docx`
> 实现方式：C++ / Qt 6（Qt Widgets），仅 Windows 平台
> 标记说明：✅ 题目明确要求　⭐ 自选拓展功能

---

## 总览

三种角色（管理员 / 售票员 / 乘客），围绕**一张班次表**和**一张票表**，跑一条主线：

> 管理员定班次 → 乘客查班次 → 售票员卖票 → 售票员退票

统计：题目明确要求 **18 项**，自选拓展 **9 项**，合计 **27 项**。

## 六、票务规则（横跨售票员和乘客）

| # | 规则 | 来源 |
|---|---|---|
| 29 | **售票条件**（三条全部满足才能卖）：① 已订票人数 < 额定载量　② 当前时间 < 发车时间　③ 当前日期在该车次的提前售票期内 | ✅ |
| 30 | **退票条件**（两条全部满足才能退）：① 车次尚未发出　② 距发车时间 ≥ 30 分钟 | ✅ |
| 31 | **实名制限购**：同一张身份证，**同一车次 + 同一乘车日期**只能买一张 | ✅ |
| 32 | **余票计算**：余票 = 额定载量 −（该车次该日期的已售票数） | ✅ |

### 关于题目两处歧义的实现约定

1. 原文"当本车次发出前半小时才可以退票"语义模糊。本系统按 **"距发车不足 30 分钟则不能退票"** 实现。
2. 原文"每张身份证只允许购买一张火车票"在支持多天车次后不合理（乘客应能购买不同日期的车票）。本系统按 **"同一车次 + 同一乘车日期限购一张"** 实现。

> 以上两点在答辩时主动说明，属设计取舍。

## 一句话概括

三个角色登录 → 管理员维护班次（存 `number.dat`）→ 乘客查班次 / 查路线 / 生成时刻表（存 `sort.dat`）→ 售票员按规则售票退票（存 `tickets.dat`），全程图形界面。

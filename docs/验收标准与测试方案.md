## 一、验收总原则

1. **每个里程碑结束时，工程必须处于「能编译」的状态** —— 不允许 long-lived 的坏状态。
2. **验收动作必须可复现** —— 写清楚具体命令或具体操作步骤，不能靠"感觉对了"。
3. **区分两种验收能力**：
   - **本机可验收**：逻辑层（M1~M3），本机能编译 **且能运行**，结果可打印验证。
   - **必须 Windows 验收**：界面层（M4 以后），本机无图形环境，只能编译，运行效果必须你在 Windows 上看。
4. **通过标准是"执行出来的"，不是"看出来的"** —— 能用脚本/自检程序判断的，绝不靠肉眼。

## 二、测试的三个层次

| 层次 | 时机 | 能抓住 | 执行者 |
|---|---|---|---|
| **① 编译验证** | 每写完一个文件 | 语法错误、拼写错误、漏 include、类型不匹配、信号槽签名不匹配、`Q_OBJECT` 漏写 | 我（本机） |
| **② 本地运行验证** | M1 / M2 / M3 每步结束 | **逻辑错误**：序列化往返、排序、规则判定、边界条件 | 我（本机控制台） |
| **③ Windows 运行验证** | M0、M4、M5、M6、M7 | 界面布局、字体、DPI、真实交互、可执行文件能否脱离 Qt 运行 | **你** |

> **关键区别**：M1~M3 是纯逻辑层，**不依赖界面**，所以本机能编译也能运行。
> M4 之后有界面了，本机没有显示设备，**只能编译不能运行** —— 这部分必须靠你在 Windows 上验收。

`src/core/AppClock.h/.cpp`、`src/core/FileStore.h/.cpp`、`tools/selftest.cpp`

**验收标准（必须逐条通过）**：

| # | 验收项 | 验收方式 | 期望结果 |
|---|---|---|---|
| 1 | 编译零错误 | `cmake -S . -B build && cmake --build build` | 构建成功 |
| 2 | 自检程序全部 PASS | 运行 `TrainticketSelfTest` | 输出全部 `[PASS]`，无 `[FAIL]` |
| 3 | 首次运行无数据目录 | 删除整个 `data/` 后运行 | 自动创建，**不崩溃** |
| 4 | **写入→读回逐字段一致** | 造 4 条班次写入，重新 load 后逐字段比对 | 每个字段完全相同 |
| 5 | 中文往返 | 站名"南京南""上海虹桥" | 不乱码、不丢字 |
| 6 | `QMap<QDate,int>` 往返 | `soldByDate` 写入多个日期 | 键值完全一致 |
| 7 | 多天数据不串 | 同一车次两个日期不同票数 | 各自独立、不覆盖 |
| 8 | 文件损坏不崩溃 | 改掉文件头魔数 | 返回失败 + 明确提示 |
| 9 | 空文件不崩溃 | 建 0 字节 `number.dat` | 返回失败，不崩溃 |
| 10 | 时间开关正确 | `setMock()` / `clearMock()` | `now()` 变化符合预期 |

> **第 4 项是最关键的一项。**
> 文件读写的典型失败模式是"能读出来但字段错位"（比如 `hours` 读成了 `capacity`），
> 这种错误**不会报错**，只有逐字段比对才能发现。

## 六、Debug 流程与责任分工

| 故障场景 | 谁介入 | 处理方式 |
|---|---|---|
| 本机编译报错 | **我**（你不参与） | 直接修复 |
| 本机运行结果不对 | **我**（你不参与） | 打印中间值定位；必要时用 gdb |
| 本机能编、Windows 编不过 | **你贴报错** | 一次来回修好（版本已对齐，概率很低） |
| Windows 能编、界面不对 | **你描述或截图** | 我调整布局/样式参数 |
| Windows 运行崩溃 | **你贴 Qt Creator 调用栈** | 我按栈定位 |
| 打包后缺 DLL | **你贴错误提示** | 我从 Qt 的 bin 目录补齐运行时 |

### 三条让 Debug 变简单的前置设计

1. **所有业务函数返回 `Result`（`ok` + `message`）** —— 出错时那条 `message` 通常直接说明原因，不用猜。
2. **`reconcile()` 对账** —— 万一计数与票表不同步，重启自动纠正，不用手改二进制文件。
3. **自检程序用自定义 `CHECK(条件, 说明)` 宏，不用 `assert`** ——
   因为 `assert` 在 Release 构建下会被 `NDEBUG` 关掉，测试会"假装通过"。
